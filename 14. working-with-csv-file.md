# Working with CSV Files — `pandas.read_csv()` Deep Dive

## Context: Why Data Acquisition Matters

Machine learning quality depends heavily on data quality — a good algorithm fed poor/little data underperforms, while a weak algorithm fed abundant good data can still do well. Before any modeling can happen, you need to know how to **get data in** from various sources.

This note covers the first and most common source: **CSV files**, via `pandas.read_csv()`.

### The Bigger Picture — Common Data Sources

| Source | Notes |
|---|---|
| **CSV** | Comma-Separated Values — most common initial format for ML/data science work |
| **JSON** | Universally accepted format for data exchange between programming languages/APIs |
| **SQL databases** | Common in production systems; query and pull as needed |
| **APIs** | Fetch data directly from a service's API when available |
| **Web scraping** | Used when there's no API and data lives on a website you don't control — a parser navigates the page's HTML and extracts what's needed |

Covering CSV, JSON, SQL, and APIs well handles the large majority of real-world data-loading needs.

## CSV vs TSV

- **CSV (Comma-Separated Values):** each row is one line; values within a row are separated by commas.
- **TSV (Tab-Separated Values):** same structure, but values are separated by tabs instead of commas. Occasionally you'll get datasets in this format and need to handle it explicitly.

## Loading a CSV — the Basics

`pd.read_csv()` can load data from:
- **A local file path** — pass the relative or absolute path to the file.
- **A URL** — if the CSV is hosted remotely and you don't have direct file access, you can fetch it in code (e.g., using the `requests` library to `GET` the URL and read the response content), rather than manually downloading it first.

`read_csv()` has ~15–16 parameters worth knowing well — mastering them means you're rarely stuck when a CSV doesn't load cleanly. The official pandas documentation for `read_csv` lists them all, each written to handle a specific real-world messiness.

## Key Parameters

### 1. `sep` (separator)

- **Default:** comma (`,`).
- If a file uses a different delimiter (e.g., tab), loading with the default `sep` causes everything to collapse into a single column.
- **Fix:** explicitly pass `sep='\t'` (or whatever the actual delimiter is).

### 2. `names` — custom column names

- Problem: if a file has no header row, pandas will treat the first data row as the column headers by mistake.
- **Fix:** pass a list of column names via `names=[...]`. You then need to infer sensible names yourself from the data (e.g., serial number, movie name, release year, rating, number of votes).

### 3. `index_col` — set a column as the index

- If your data already has an ID-like column that duplicates the auto-generated index and isn't otherwise useful, you can designate it as the DataFrame's index instead of keeping it as a regular column.
- **Usage:** `index_col='column_name'`. This replaces the default auto-generated index.

### 4. `header` — which row holds column names

- Problem: sometimes a parser mistakes the actual header row for a normal data row when the header itself was written with a stray prefix or in an unusual position, causing pandas to auto-generate column names (0, 1, 2, ...) or misplace the real header inside the data.
- **Fix:** explicitly set `header=0` (or whichever row index actually contains the header) so pandas knows to treat that row as column names rather than data.
- Note: this is a **different problem** from missing headers (`names`) — one is "there is no header row at all," the other is "there is a header row, but pandas isn't recognizing it as one."

### 5. `usecols` — load only specific columns

- Not every column is needed for a given ML task. Rather than importing everything and dropping columns afterward, you can specify upfront which columns to load.
- **Usage:** `usecols=['enrolled', 'gender', 'education_level']` — only those columns come back in the DataFrame.
- This is the simplest way to trim columns at load time (more advanced filtering options exist too, but this covers most needs).

### 6. `squeeze` — return a Series instead of a DataFrame

- If you only need a **single column**, `squeeze=True` returns it as a pandas **Series** rather than a single-column DataFrame.
- Niche parameter, but occasionally convenient.

### 7. `skiprows` / `nrows` — control which rows load

- **`skiprows`:** skip specific rows when reading.
  - Pass a list of row numbers, e.g. `skiprows=[0, 1]` to skip the first two rows — rows don't need to be consecutive; you can skip arbitrary rows (e.g., `skiprows=[0, 2]`).
  - Can also accept a **function**: write custom logic to decide which rows to skip (e.g., skip only rows that are multiples of 5, or skip rows matching some condition).
- **`nrows`:** limit how many rows to import, e.g. `nrows=100` loads only the first 100 rows.
  - Useful for very large datasets (millions/tens of millions of rows) that can't fit in memory at once — you can sample or work with a manageable chunk.

### 8. `encoding` — character encoding

- **Default:** `utf-8` — works for the vast majority of datasets.
- Some datasets (special characters, emojis, certain non-English languages) use a different encoding and will throw an error or show garbled/unreadable characters (e.g., a `UnicodeDecodeError`) when read with the default.
- **Fix options:**
  1. Open the file in a text editor (e.g., Sublime Text) and check/convert its actual encoding, or
  2. Determine the correct encoding and pass it explicitly, e.g. `encoding='latin-1'`.
- If you see garbled text or boxes/question-mark characters instead of proper text after loading, this is very likely an encoding mismatch.

### 9. `error_bad_lines` / `on_bad_lines` — malformed rows

- Problem: sometimes a small number of rows in an otherwise-consistent CSV have the wrong number of fields (e.g., most rows have 5 columns, but a few rows have 6), and by default `read_csv` throws an error and refuses to load (e.g., "Expected N fields in line X, saw N+1").
- **Fix:** use `error_bad_lines=False` (older pandas) or `on_bad_lines='skip'` (newer pandas) to skip the malformed lines and load the rest of the data, with a warning printed for each skipped line.

### 10. `dtype` — control column data types

- By default, pandas infers a column's dtype from its contents. Sometimes this isn't what you want — e.g., a numeric column with only a few discrete values (like a binary target: 0/1) may get inferred as `float`, wasting memory unnecessarily.
- **Fix:** pass a dictionary mapping column name → desired dtype, e.g. `dtype={'target': 'int'}`.
- Useful to check with `.info()` afterward to confirm memory usage/type improved.

### 11. `parse_dates` — convert columns to datetime

- By default, `read_csv` loads date-like columns as plain **strings/objects**, not actual datetime values — so you can't use date functionality (extracting month, day, year, date arithmetic, etc.) on them directly.
- **Fix:** pass `parse_dates=['column_name']` (a list of column names) to have pandas convert that column to a proper `datetime64` dtype.
- After this, you can use datetime operators/attributes and do date arithmetic (e.g., subtracting two dates).
- **Combining multiple columns into one date:** if a dataset has separate `year`, `month`, `day` columns instead of one date column, you can pass a **list of lists** to `parse_dates` — each inner list names the columns to combine — and pandas will merge them into a single new datetime column (pandas' documentation also shows a dictionary-based syntax for naming the resulting combined column).

### 12. `converters` — apply a custom function to a column while loading

- Lets you apply a transformation function to every value in a specified column as the data is read in.
- **Example use case:** an IPL dataset has full team names (e.g., "Royal Challengers Bangalore"), but you want short codes (e.g., "RCB") instead. Write a function that maps full names to short codes, then apply it at load time.
- **Usage:**
  ```python
  def rename_team(name):
      if name == "Royal Challengers Bangalore":
          return "RCB"
      return name

  df = pd.read_csv('file.csv', converters={'team1': rename_team})
  ```
- Any number of transformations can be applied across any number of columns this way — a genuinely powerful technique for cleaning data during the load itself.

### 13. `na_values` — customize what counts as missing/NA

- By default, pandas recognizes common representations of missing data (e.g., blank cells) as `NaN`.
- Sometimes a dataset uses a **placeholder** for missing values instead (e.g., the string `"Male"` used as a stand-in for "no data" in some malformed dataset, or values like hyphens/percent signs used as sentinels).
- **Fix:** pass `na_values=['Male']` (a list of any values you want treated as missing) so pandas converts every instance of that value to `NaN` instead of treating it as real data.
- Use with care — only mark a value as NA if it's genuinely meant to represent missing data in your specific dataset, not real data that happens to share the value.

### 14. `chunksize` — load large files in chunks

- Problem: a very large file (e.g., millions of rows) may not fit comfortably in memory, so operations across the whole thing at once can fail or be impractical.
- **Fix:** `chunksize=N` returns an **iterable of DataFrames**, each with (up to) `N` rows, instead of one giant DataFrame.
- **Usage pattern:**
  ```python
  for chunk in pd.read_csv('big_file.csv', chunksize=5000):
      # chunk is a DataFrame with up to 5000 rows
      # apply whatever operation you need here
      print(chunk.shape)
  ```
- Any transformation, filtering, or aggregation you need can be run inside the loop, one chunk at a time — this is the standard way to handle datasets too large to load in one shot.

## Quick Reference Table

| Parameter | Purpose |
|---|---|
| `sep` | Set the delimiter (default `,`) |
| `names` | Supply column names when there's no header row |
| `index_col` | Use an existing column as the DataFrame index |
| `header` | Specify which row holds the actual column headers |
| `usecols` | Load only specific columns |
| `squeeze` | Return a Series instead of a DataFrame for single-column loads |
| `skiprows` | Skip specific rows (list or custom function) |
| `nrows` | Limit the number of rows loaded |
| `encoding` | Set character encoding (default `utf-8`) |
| `error_bad_lines` / `on_bad_lines` | Skip malformed rows instead of erroring out |
| `dtype` | Force specific data types per column |
| `parse_dates` | Convert column(s) to proper datetime, optionally merging multiple columns |
| `converters` | Apply a custom function to a column's values while loading |
| `na_values` | Define custom placeholder values to treat as missing (`NaN`) |
| `chunksize` | Load a large file in manageable chunks via an iterator |

## Key Takeaway

`read_csv()` is deceptively deep — most tutorials cover only `sep` and maybe `header`. Knowing the fuller parameter set (encoding issues, malformed rows, custom NA values, dtype control, date parsing, chunked loading) means CSV loading stops being a recurring source of friction and becomes a solved problem you can handle in one line, whatever shape the file arrives in.
